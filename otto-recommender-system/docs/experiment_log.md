# OTTO 推荐系统实验日志

## 实验假设与核心矛盾

本阶段假设是：在无时间泄漏的会话前缀上构建候选，使用静态行为特征、图召回分数和 SASRec 序列分数，再为 Click、Cart、Order 分别训练 LightGBM 排序模型，可以提高各业务目标的 Top-20 排序质量。核心矛盾是：候选池需要覆盖尾部行为，而 Order 标签稀疏；扩大候选覆盖会引入大量困难负样本，模型必须区分“被点击但未购买”和“图上共现强但未转化”的商品。

本阶段采用三个独立目标模型，不把 Click、Cart、Order 强行合并为一个目标。最终验证提交按 `session_type` 使用对应模型：Click 使用 B，Cart 使用 B，Order 使用 C。

## 数据与防穿越边界

验证会话采用动态 prefix/suffix 切分：每个会话保留前缀作为特征、召回和排序输入，后缀作为标签来源；长度小于 2 的会话不进入该验证池。所有特征必须满足：

```text
t_feature < t_label
```

## 特征构建与数学表达

候选侧使用图召回分数、候选排名、局部会话交互统计、全局 item 统计、会话统计和 SASRec 输出。关键特征定义为：

```text
delta_t(s, i) = t_last(s) - t_last(s, i)
conversion_rate = (cart + order + lambda * mu) / (click + lambda)
is_repeated_item = 1[n_total(s, i) > 0]
```

静态 item 特征包括全局 Click/Cart/Order 次数、转化率及漏斗比率；session 特征包括长度、去重商品数、驻留时长、Cart/Order 次数和 window-shopping 标记；candidate/session 交叉特征包括局部交互次数及局部行为类型计数。缺失交互时间使用物理极值填充，以区分“未触达”与“近期触达”。

SASRec 使用 prefix 序列训练，并将 `nn_global_score` 与 `nn_explore_score` 写入候选特征表。实验证明神经特征被 LightGBM 实际使用，但当前 checkpoint 曾出现真实 `aid=0` 与 padding ID `0` 冲突，导致 NaN。当前输出已用 `fill_nan(0.0)` 处理；正式重训应将真实 aid 映射为 `aid + 1`，保留 0 为 padding，并重新生成 checkpoint：[待补充: 修复 ID 映射后的 SASRec 重训结果]。

## 离线评估与指标对比

评估指标为后缀真实标签上的 NDCG@20。对每个 session 取预测 Top-20，命中位置 `r` 的折扣为 `1 / log2(r + 1)`，再除以该 session 的理想 DCG；最终对验证 session 求平均。

### Order 消融

| 模型 | 采样配比 | 训练行数 | 正样本数 | NDCG@20 |
| --- | --- | ---: | ---: | ---: |
| A | 1:8:10:2 | 79,202 | 3,769 | 0.790142 |
| B | 1:10:8:2 | 79,150 | 3,769 | 0.788910 |
| C | 1:6:12:2 | 79,304 | 3,769 | **0.790456** |

Order C 的会话命中为 2,640 / 2,902 = 90.97%。因此 Order 采用 C；B 对点击未购买负样本的额外加权没有带来收益。

### Click 消融

| 模型 | 训练行数 | 正样本数 | NDCG@20 |
| --- | ---: | ---: | ---: |
| A | 1,823,948 | 86,761 | 0.288034 |
| B | 1,823,860 | 86,761 | **0.292191** |
| C | 1,823,298 | 86,761 | 0.279619 |

Click 采用 B。增加“仅点击未买”困难负样本能改善 Click 排序；增加高共现负样本则明显损害 Click NDCG。

### Cart 消融

| 模型 | 训练行数 | 正样本数 | NDCG@20 |
| --- | ---: | ---: | ---: |
| A | 365,513 | 17,417 | 0.637324 |
| B | 365,828 | 17,417 | **0.637668** |
| C | 366,058 | 17,417 | 0.635713 |

Cart 采用 B，优势很小，需避免把该差异解读为稳定提升。[待补充: 多随机种子置信区间或重复实验结果]。

### 融合策略审判

未经校准的三个模型概率直接加权会破坏各目标的排序尺度。验证结果：

| Click/Cart/Order 权重 | Click NDCG | Cart NDCG | Order NDCG |
| --- | ---: | ---: | ---: |
| 0.2 / 0.3 / 0.5 | 0.284197 | 0.609109 | 0.760574 |
| 0.1 / 0.2 / 0.7 | 0.282139 | 0.590075 | 0.780018 |
| 0 / 0 / 1 | 0.245662 | 0.530349 | **0.790456** |

融合被淘汰，原因是它在三个目标上都低于相应的独立模型，尤其损害 Cart 和 Order。最终提交保持按 `session_type` 独立重排。

### 特征重要性

Order C 的 gain 主要来自：

| 特征 | Gain 占比或数值 |
| --- | ---: |
| `local_cart_count` | 56.52% |
| `local_interaction_count` | 13.85% |
| `score` | 5.78% |
| `session_cart_count` | 2.90% |
| `session_duration` | 2.64% |

SASRec 特征已经进入有效决策路径：`nn_global_score` gain 为 5,281.886、split 为 1,567；`nn_explore_score` gain 为 4,369.173、split 为 259。`session_is_window_shopping` gain 为 0，说明当前模型没有使用该特征，后续应检查定义、取值分布和是否被其他会话特征完全替代。

## 性能瓶颈与物理开销

本地 WSL 阶段使用 16 个 Parquet 分块处理 1,420 万候选行。SASRec 一轮训练耗时约 4.0--4.3 秒；候选离线打分生成 16 个输出分块。LightGBM 单模型训练耗时约 14--19 秒。当前已知磁盘开销是候选特征约 530 MB；峰值 RSS、GPU 显存、各阶段峰值内存和完整推理耗时尚未记录：[待补充: CPU 峰值内存、GPU 峰值显存、磁盘总占用、分块单次峰值]。

主要物理风险有两项：

1. 将 1,420 万行候选一次性转为 Pandas 或一次性 Join，可能造成内存峰值；当前流程应继续使用 Polars Lazy/分块落盘。
2. SASRec 的 padding ID 冲突会污染序列表示并产生 NaN；必须完成 `aid + 1` 映射后再进行正式比较。

每个 session 的候选数分布尚未记录，无法判断 Top-20 截断前是否存在大量候选不足：[待补充: candidates/session 的 min、median、p95、max]。

## 当前结论与下一步

当前可复现的本地验证策略为：Click=B、Cart=B、Order=C，按目标类型独立输出 Top-20。该结论只适用于当前 session-tail 验证切分和候选池，不能直接外推 Kaggle 测试集。下一轮策略研究应先完成 SASRec ID 修复、多随机种子重复、候选数分布和资源峰值记录，再研究召回通道或特征组消融。
